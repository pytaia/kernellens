# 08. Данные

Код: `nullgraft/data/`, `scripts/register_vhp.py`, `nullgraft/config.py`.

## NLM Visible Human Project

Тело сканировали на КТ, затем послойно замораживали и фотографировали каждый срез. Это единственный
открытый набор, где у КТ есть **не томографический** эталон той же анатомической плоскости: эталон $x$
не произведён никаким декодером, и поэтому на нём можно честно проверять галлюцинации.

* Оригинал: https://datadiscovery.nlm.nih.gov/Images/Visible-Human-Project/ux2j-9i9a/about_data
* DICOM: коллекция `NLM-Visible-Human-Project` в NCI Imaging Data Commons (манифесты:
  https://zenodo.org/records/12690050), загрузка через `idc-index`.

Пакет ничего не скачивает: путь передаётся через `--data` или `data.path` в конфиге.

### Формат папок

* **КТ:** папка DICOM (`*.dcm` или файлы без расширения с сигнатурой `DICM`) либо папка `.png/.tif/.npy`
  с файлом `ct_meta.json`:
  `{"pixel_spacing_mm": [dy, dx], "slice_spacing_mm": dz, "rescale": [slope, intercept]}`.
* **Криосрезы:** папка цветных изображений; разрешение в плоскости передаётся явно (`--cryo-pixel-mm`).

Файлы сортируются естественным порядком (`slice2` раньше `slice10`), DICOM — по $z$ из `ImagePositionPatient`.

### Геометрия только из файлов

Цифры из описания проекта 1995 г. (1 мм, 512×512, 2048×1216) **не используются**. `nullgraft report CT_DIR`
печатает то, что реально найдено в файлах:

* размеры пикселя и формы срезов;
* медиану и диапазон шага по $z$;
* монотонность нумерации и диапазон $z$.

Это стоит проверить до любых экспериментов.

### Единицы

$\mathrm{HU} = \text{raw}\cdot\text{slope} + \text{intercept}$, затем $\mu = \mu_w (1 + \mathrm{HU}/1000)$ с
обрезкой снизу нулём; $\mu_w = 0.0192\ \text{мм}^{-1}$ (вода около 70 кэВ). Криосрез переводится в яркость
$Y = 0.2126R + 0.7152G + 0.0722B$, масштаб берётся по диапазону целого типа (uint8 → /255), а не по содержимому.

## Регистрация криосрезов на КТ

Ткани деформируются при заморозке и резке, поэтому КТ и криосрез попиксельно не совпадают. Остаточное
несовпадение геометрии **нельзя** принимать за «деталь». `scripts/register_vhp.py` для каждой пары срезов:

1. Приводит криосрез к сетке КТ: пересэмплирование с антиалиасингом под совпадение мм/пиксель и центрирование.
   Исходное разрешение хранится отдельно и нужно для выбора мелких деталей.
2. **Аффинная регистрация** (6 параметров в 2D) по метрике взаимной информации Маттеса,
   $I(F;M) = H(F) + H(M) - H(F, M)$ по совместной гистограмме. У КТ и фотографии разный контраст, поэтому
   разность интенсивностей как метрика не подходит. Инициализация — по моментам, оптимизатор —
   градиентный спуск.
3. **Деформируемая регистрация** поверх аффинной: B-spline (FFD) с сеткой контрольных точек 8×8,
   L-BFGS-B, та же метрика.
4. Лог в `registration_log.json`:
   * **Dice** масок тела (порог Оцу) до и после;
   * **TRE** — средняя ошибка $\lVert T(\mathbf{p}_{CT}) - \mathbf{p}_{cryo}\rVert$ в мм по ручным ориентирам
     (`--landmarks`) до и после.

Срезы с плохими TRE/Dice нужно исключать из экспериментов. Срез, на котором регистрация упала, помечается
`"excluded": true`, и прогон продолжается.

## Разбиение train/test без утечки

Соседние срезы КТ (около 1 мм) почти одинаковы. Если делить по отдельным срезам, тест «видит» почти те же
изображения, что и обучение. Поэтому:

* `block_split` отдаёт в train или test **целые блоки** по `block_size` подряд идущих срезов и выбрасывает
  срезы в зазоре `gap` у каждой границы train/test. Тест проверяет, что любой тестовый срез отстоит от
  любого обучающего больше чем на `gap`;
* `region_split` делит по метке анатомической области среза.

Субъектов всего 2 (VHP), с CVH и VKH до 4, зато срезов тысячи. Выводы о межсубъектной обобщаемости ограничены.

## Дополнительные наборы (по запросу к авторам)

* Chinese Visible Human: криосрезы 3072×2048 (~170 мкм), КТ 512×512.
* Visible Korean Human: шаг 0.2 мм, есть сегментация органов. Её можно передать в
  `ArtifactIndex.build(segmentations=...)` (разметка «структура/фон») и использовать для Dice.

Подключаются тем же интерфейсом (`npy` или `vhp_registered`).

## Синтетика

Для проверки пайплайна без данных:

* `shepp_logan(size)` — фантом Шеппа–Логана из `skimage.data`;
* `random_ellipse_phantom` — «тело» с внутренними эллипсами;
* `synthetic_volume(n, size)` — стопка срезов с медленно дрейфующими эллипсами. Соседние срезы почти
  совпадают, как в реальной КТ, поэтому на ней видна разница между правильным и неправильным разбиением.
