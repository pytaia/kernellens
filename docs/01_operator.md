# 01. Прямой оператор: модель измерения КТ

Код: `nullgraft/operators.py`.

## Суть

Томограф измеряет интегралы ослабления вдоль лучей. Весь пакет опирается на модель

$$
y = A x + e, \qquad \lVert e \rVert_2 < \varepsilon ,
$$

где $A$ — линейный оператор (дискретное преобразование Радона). Остальным модулям нужны только две
операции: $x \mapsto Ax$ и $s \mapsto A^\top s$. Матрица $A$ целиком не строится: в разреженном виде
она кэшируется, только если влезает в бюджет памяти.

## Непрерывная модель

Для направления $\omega(\theta) = (\cos\theta, \sin\theta)$ преобразование Радона функции $f$ равно

$$
(\mathcal{R} f)(\theta, t) = \int_{\mathbb{R}} f\big(t\,\omega(\theta) + s\,\omega^\perp(\theta)\big)\, ds .
$$

Важное свойство, используемое в тестах: интеграл проекции по детектору равен массе изображения при любом угле,

$$
\int \mathcal{R} f(\theta, t)\, dt = \int f(\mathbf{p})\, d\mathbf{p} .
$$

## Дискретизация pixel-driven (бэкенд `pixel`)

Пиксель $j$ с центром $\mathbf{p}_j$ — квадрат единичной площади со значением $x_j$. Центры пикселей
$\mathbf{p}_j = (j_c - \tfrac{W-1}{2},\ \tfrac{H-1}{2} - j_r)$ в пикселях, центры бинов детектора
$t_k = (k - \tfrac{n_{det}-1}{2})\,\Delta t$.

**Параллельный пучок.** Для угла $\theta_a$ центр пикселя проецируется в $t_j = \mathbf{p}_j \cdot \omega(\theta_a)$.
Дробный индекс бина $f_j = t_j/\Delta t + \tfrac{n_{det}-1}{2}$ делит вклад пикселя между соседними бинами
$k_0 = \lfloor f_j \rfloor$ и $k_0+1$ с линейными весами $w_1 = f_j - k_0$, $w_0 = 1 - w_1$:

$$
A_{(a,k_0),\,j} = \frac{w_0}{\Delta t}, \qquad A_{(a,k_0+1),\,j} = \frac{w_1}{\Delta t}.
$$

Множитель $1/\Delta t$ сохраняет массу: $\sum_k A_{(a,k),j}\,\Delta t = 1$ (площадь пикселя). Это дискретный
аналог свойства выше; тест `test_parallel_projection_matches_line_integrals` проверяет его вместе с
аналитическими интегралами диска $2\sqrt{r^2 - t^2}$.

**Веерный пучок (плоский детектор).** Источник находится на расстоянии $D_{so}$ от изоцентра, детектор — на
$D_{od}$ за ним, $D_{sd} = D_{so} + D_{od}$. Для пикселя:

* глубина вдоль центрального луча $L_j = D_{so} + \mathbf{p}_j \cdot \omega$;
* боковое смещение $\ell_j = \mathbf{p}_j \cdot \omega^\perp$;
* координата на детекторе $u_j = \ell_j\, D_{sd} / L_j$, увеличение $m_j = D_{sd}/L_j$;
* косинус веерного угла $\cos\gamma_j = L_j / \sqrt{L_j^2 + \ell_j^2}$.

Ширина луча в точке пикселя, измеренная поперёк луча, равна $\tfrac{\Delta u}{m_j}\cos\gamma_j$. Поэтому вес
пикселя — величина, обратная этой ширине:

$$
\text{scale}_j = \frac{m_j}{\Delta u \cos\gamma_j}.
$$

Число бинов по умолчанию покрывает диагональ изображения. Для веера касательная из источника к описанной
окружности радиуса $r$ даёт $u_{max} = D_{sd}\, r / \sqrt{D_{so}^2 - r^2}$. Шаг детектора по умолчанию
$\Delta u = D_{sd}/D_{so}$, то есть 1 пиксель в изоцентре.

## Сопряжённый оператор и почему он должен быть точным

$A^\top$ собирает значения синограммы обратно в пиксели **с теми же весами**. Поэтому для любых $x, s$

$$
\langle A x, s\rangle = \langle x, A^\top s\rangle
$$

с точностью до округления; это проверяет dot-test (`test_pixel_backend_adjoint_is_exact_transpose`).

Точность здесь принципиальна. LSQR (см. [02](02_nullspace.md)) строит пространства Крылова оператора
$A^\top A$. Если «сопряжённый» оператор на самом деле им не является, итерации не сходятся к решению
минимальной нормы, и проекция на ядро перестаёт быть проекцией. Поэтому `skimage.radon` не годится
по умолчанию: его пара `radon`/`iradon(filter=None)` лишь приближённо транспонирована, и после
перемасштабирования на $2N_\theta/\pi$ остаётся расхождение.

## Реализация и производительность

* **Кэш матрицы.** Число ненулевых элементов $\approx 2\,N_{pix} N_\theta$ (по два бина на пиксель и угол).
  Хранение — CSR в float64 (12 байт на ненулевой элемент). Пример: 128²×60 даёт 2.0 млн ненулевых
  элементов, около 24 МБ. Для 512²×360 это уже 189 млн (около 2.3 ГБ), так что при бюджете по умолчанию
  оператор работает без матрицы. Float64 выбран по замеру: умножение матрицы float32 на вектор float64
  заставляет scipy перекастовывать матрицу на каждом вызове, и это в 3.4 раза медленнее.
* **Путь по носителю.** Если $x = 0$ вне маски $R$, то $Ax = \sum_{j\in R} A_{:,j}\, x_j$: считается только по
  пикселям $R$ за $O(|R|\,N_\theta)$ вместо $O(N_{pix} N_\theta)$. Отсюда же маска лучей
  $\operatorname{supp}(A\,\mathbb{1}_R)$ (`ray_mask`).
* **Батчи.** Вход $(B, H, W)$ обрабатывается одним умножением разреженной матрицы на матрицу $N_{pix}\times B$.
* **Норма** $\lVert A\rVert_2$ оценивается степенным методом: $v \leftarrow A^\top A v / \lVert A^\top A v\rVert$,
  тогда $\lVert A^\top A v\rVert \to \sigma_{max}^2$. Она нужна для масштабирования параметров TV-ADMM.

## Бэкенды

| Бэкенд | Геометрии | $A^\top$ точный | Когда использовать |
|---|---|---|---|
| `pixel` | parallel, fan | да | по умолчанию на CPU |
| `astra` | parallel, fan | CPU — да, CUDA — приближённо | выбирается автоматически при установленном ASTRA; физически точнее |
| `skimage` | parallel, квадратные изображения | нет | эталон для сверки `radon` |

## Ограничения

* Модель линейная: beam hardening, рассеяние и пуассоновская статистика не учитываются.
* Pixel-driven интерполяция даёт высокочастотные погрешности, когда шаг детектора близок к пикселю.
  Для физически точных данных используйте ASTRA.
